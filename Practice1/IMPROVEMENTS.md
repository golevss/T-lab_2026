# Улучшения модели

Основной вариант **обновлён**. Активная модель: `results/upgrades/active.cbm`, 73 признаков; конфигурация — [active_model.json](active_model.json). Исходные эксперименты и их результаты сохранены.

## Что проверено

- Спектральные признаки в первом проекте; во втором они уже входят в baseline.
- ItemKNN: cosine совместных просмотров со shrinkage `coocc/(coocc+10)`, без диагонали, top100 соседей; суммы по всей истории, с затуханием half-life=7 и по последнему объекту.
- Расширение: ItemKNN + граф32 + окна 2/14 дней и затухание 3/14 дней; max/mean доли интереса по **всем** жанрам кандидата all/30, не только первому. Всего 73 признака.
- [YetiRank с NDCG@10](https://catboost.ai/docs/en/concepts/loss-functions-ranking?lang=en): 120 итераций, depth=5, lr=0.08. В проверенном бюджете уступил; это не вывод о всех ranker-конфигурациях.
- Fallback для cold user в representation второго проекта.

[EASE](https://arxiv.org/abs/1905.03375) рассмотрен, но не запускался: плотная матрица O(I²) и решение системы на каждом срезе. Трансформер/GNN отложены: короткая история KION и last-watch вместо сырой последовательности; их бесполезность не утверждается.

## Использование

`predict.py` — пакетный вход системы; по умолчанию использует активную модель. CSV кандидатов содержит `user_id,item_id`, объекты должны быть в прошлом каталоге. История — `data/events.pkl`, подготовленная обычным prepare; label из кандидатов игнорируется.

```powershell
python predict.py --candidates candidates.csv --cutoff 2021-08-16 --output results/upgrades/recommendations.csv
python train_active.py
python -m unittest -v test_protocol.py test_upgrades.py
```

В графовом проекте дополнительно: `--mode representation` (с подтверждённым fallback), `--mode representation_raw` (исходный вариант). `score` — вероятность sampled-label для классификатора, не CTR. При ranker это некалиброванный ranking score. Признаки считаются пакетом; это не готовый онлайн-сервис с измеренным SLA. Матрица ItemKNN хранится разреженно с top100, построение совпадений может уплотняться на больших каталогах; промышленный масштаб не проверен.

`run_all.py` после исходного эксперимента переобучает активную модель по зафиксированной конфигурации. `train_active.py` использует кэш с ключом истории/кандидатов/исходного ZIP; параметры по test не меняются. Старые метрики автоматически не заменяются метриками активной версии: они относятся к исходному исследованию.

Матрицы/queries удалены как пересчитываемые; перед переобучением выполните prepare. events.pkl сохранён для предсказаний. Воспроизведение улучшений без подбора по новому тесту:

```powershell
python prepare.py --users 10000 --seed 42
python tune.py --project . --kind features
python prepare_confirmation.py
python confirm_upgrade.py
python train_active.py
```

`tune.py` только повторяет скрининг и сохраняет выбор; не переключает активную модель. Подтверждение использует сохранённую selection и exclusion-ID; `confirm_upgrade.py` сверяет итог с сохранёнными показателями. Конфигурация активной версии остаётся зафиксированной в active_model.json. Подробности — results/upgrades: протокол, оба сравнения, ID новой когорты/исключений, предсказания и проверки. Кэши `.pkl` можно пересоздать.
